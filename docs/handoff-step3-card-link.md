# 서비스 상세 페이지 — 3단계 구현 지시서

> 데스크톱 앱 세션(기획·설계)에서 작성한 문서를 Claude Code CLI(구현)로 넘긴다.
> 1단계(데이터·초안), 2단계(`/services/[slug]` 페이지, 커밋 `ee5d741`)는 끝났다. 이 문서는 **3단계만** 다룬다.
> 규칙: 이 단계가 끝나면 멈추고, 변경 파일 목록과 확인 방법을 보고한다. push는 오너 확인 후.
> 페이지별 메타데이터(title·canonical·OG)는 2단계에서 이미 끝났으므로 이번 범위에 없다.

## 1. 목표

메인의 운영 중 서비스 카드를 누르면 **상세 페이지(`/services/[slug]`)로 이동**하고, 이미 서비스를 아는 재방문자를 위해 카드 안에 **운영 화면으로 바로 가는 작은 링크("바로 열기 ↗")**를 둔다.

지금은 카드 전체가 `CardLink`(외부 URL, 새 탭)로 감싸져 있다.

## 2. 먼저 읽을 것

- `src/components/ServiceCard.tsx`, `CardLink.tsx`, `ArchiveCard.tsx`, `Services.tsx`, `ShortcutBar.tsx`
- `src/components/ServiceDetail.tsx`, `OpenLiveButton.tsx` (2단계에서 만든 외부 링크 처리 방식)
- `docs/design/DESIGN.md` 3장(색 규칙), 6장 "운영 중인 서비스", 7장(터치 대상 44px), 8장(접근성)
- `AGENTS.md`의 지시대로, 새로 쓰는 Next.js API(`next/link` 등)가 있으면 `node_modules/next/dist/docs/`를 먼저 확인한다.

## 3. 핵심 문제: `<a>` 안에 `<a>`를 넣을 수 없다

카드 전체를 상세 페이지 링크로 두고 그 안에 "바로 열기" 외부 링크를 넣으면 **중첩 앵커**가 되어 HTML이 잘못되고, 접근성·클릭 동작이 깨진다.
**"늘린 링크(stretched link)" 패턴**으로 푼다.

- `<article>`을 `relative`로 둔다. 카드 전체를 감싸는 `<a>`는 쓰지 않는다.
- 상세 페이지로 가는 `next/link`를 **제목(h3) 안**에 두고, 그 링크의 `::after`를 `absolute inset-0`으로 펼쳐 카드 전체(스크린샷 포함)를 클릭 영역으로 만든다.
  (Tailwind 예: `after:absolute after:inset-0 after:content-['']`. 정확한 클래스는 구현자가 정한다.)
- "바로 열기" 외부 링크는 `relative z-10`으로 펼친 링크 위에 올린다.
- 두 링크가 서로 중첩되지 않는지 DOM에서 확인한다 (완료 기준 참고).

## 4. 만들 것

### 4-1. `ServiceCard.tsx` 수정

`project.detail`이 **있을 때**:
- 카드 클릭(스크린샷, 제목, 설명 어디든) → `/services/${project.slug}` (같은 탭, `next/link`)
- 카드 안에 "바로 열기 ↗" 링크 → `project.url`, `target="_blank" rel="noopener noreferrer"` (`url`이 없으면 렌더링하지 않는다)
- 레이아웃·간격·스크린샷 높이(모바일 220px / 데스크톱 300px)·배지·상태 점·메타·설명은 **지금과 똑같이** 유지한다.
- 제목 hover 밑줄은 유지한다 (`group` + `group-hover:underline`을 `<article>`에서 받는다).

`project.detail`이 **없을 때**는 지금 동작을 그대로 둔다 (`CardLink`로 외부 URL, `url`도 없으면 링크 없는 블록). 이 분기를 깨뜨리지 않는다.

### 4-2. "바로 열기 ↗" 링크 명세
- 위치: 설명 문단 아래, 카드 맨 아래. 위 간격 4px 정도.
- 모양: **버튼이 아닌 텍스트 링크.** 15px/600, 색 `ink`, 화살표 ↗ 포함, hover 밑줄. **코랄·플럼·새 버튼 스타일을 쓰지 않는다** (DESIGN.md 3장: 버튼을 더 늘리지 않는다).
- 터치 대상 높이 44px 이상 (7장). 카드 레이아웃이 어긋나지 않게 패딩이 아닌 `min-h-11` 등으로 확보한다.
- 접근성: 한 페이지에 "바로 열기"가 3개이므로 스크린리더가 구분할 수 있어야 한다. 화면에는 "바로 열기 ↗"만 보이고, `sr-only`로 서비스 이름과 "(새 탭에서 열림)"을 덧붙인다. 예: `바로 열기 ↗ <span class="sr-only"> — joBiBle_onspot, 새 탭에서 열림</span>`
- 상세 링크(제목 링크)는 내부 이동이므로 "(새 탭에서 열림)"을 붙이지 않는다.

### 4-3. `projects.ts`
고정 UI 문구를 컴포넌트에 쓰지 않는다. `servicesSection`에 필드를 추가한다.

```ts
export const servicesSection = {
  // ...기존 필드
  directLink: "바로 열기",
};
```

### 4-4. 건드리지 않는 것
- `CardLink.tsx`는 `ArchiveCard`와 상세 없는 카드의 폴백이 쓰므로 **삭제하지 않는다.**
- `ShortcutBar`(바로가기 바)의 `#slug` 앵커는 그대로 둔다. 카드의 `id={project.slug}`와 `scroll-mt-6`도 그대로.
- 지난 실험들(보관함) 카드는 바꾸지 않는다.

## 5. DESIGN.md 갱신

6장 "운영 중인 서비스"의 `카드 전체가 서비스 URL 링크 (새 탭)` 줄을 다음 취지로 고친다.
- 카드 전체는 서비스 상세 페이지 링크(같은 탭). 제목에 늘린 링크를 둔다.
- 카드 아래에 "바로 열기 ↗" 텍스트 링크(운영 URL, 새 탭)를 둔다. 상세 페이지가 없는 서비스는 예전처럼 카드 전체가 운영 URL 링크(새 탭).
- 중첩 앵커를 피하기 위한 구조라는 점을 한 줄로 남긴다.

## 6. 기록

`HANDOFF.md` 맨 위 "현재 상태"에 서비스 상세 페이지(1~3단계) 완료를 한국어로 간단히 기록한다. (`CLAUDE.md`: 완료 현황은 HANDOFF.md 맨 위)

## 7. 완료 기준

1. `npm run build` 통과, 타입 오류 없음. `npm run lint`도 통과한다.
2. 개발 서버에서 브라우저로 확인한다 (375px, 768px, 1280px).
   - 3개 카드 어디를 눌러도(스크린샷·제목·설명) `/services/onspot`, `/services/way`, `/services/goldendays`로 같은 탭에서 이동한다.
   - "바로 열기 ↗"는 해당 운영 URL이 **새 탭**에서 열리고, `rel="noopener noreferrer"`가 있으며, 상세 페이지로 이동하지 **않는다.**
   - 브라우저 콘솔에서 `document.querySelectorAll('a a').length`가 0이다 (중첩 앵커 없음).
   - 카드 레이아웃(스크린샷 높이, 배지, 간격, 3열/2열/1열 그리드)이 3단계 이전과 달라지지 않았다. 스크린샷 비교로 확인한다.
   - Tab 키 순서가 카드 링크 → "바로 열기" 순이고, 둘 다 포커스 표시가 보인다.
   - "바로 열기"의 터치 대상 높이가 44px 이상이다.
   - 바로가기 바와 모바일 "서비스 둘러보기"가 여전히 해당 카드·서비스 섹션으로 스크롤한다.
   - 상세 페이지에서 "← 전체 서비스"로 돌아오면 메인의 서비스 섹션으로 간다.
3. 접근성 점검: 가능하면 Lighthouse 접근성 점수가 이전(100)에서 떨어지지 않았는지 확인한다.
4. 한국어 커밋 메시지로 커밋한다. 빌드 중 폰트 서브셋(`pretendard-subset.woff2`)이 갱신되면 함께 커밋한다. **push는 오너 확인 후.**

## 8. 하지 않을 것 (범위 밖)
- sitemap·robots 추가 (현재 둘 다 없음. 필요하면 오너에게 제안만 한다.)
- 서비스별 OG 이미지, 추가 스크린샷, 지난 실험들의 상세 페이지
- Nav·Footer 링크를 `next/link`로 바꾸는 것 (전체 새로고침 이동이지만 동작에는 문제 없음)
- `projects.ts`의 상세 초안 문구 수정 (`TODO(owner)` 항목은 오너 검수 후)
